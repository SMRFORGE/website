The problem

AI produces numbers faster than anyone can defend them.

The person who acts on a number has to defend it later. An engineer signing a design. An auditor signing off. A regulator deciding whether to believe it. For that person, “the model produced it” is not an answer. They need to open the number up and re-derive it. In nuclear this is the whole bottleneck. Every safety-relevant number is defended to the NRC by hand, for months.

SMRFORGE adds a defensibility layer to what you deliver. It does not replace any of it.

When an agent’s work ends in a real calculation, that calculation can be sealed, independently re-run, and signed, so the engineer or regulator downstream can confirm it cold. It is the auditability, traceability, and reproducibility layer alongside a production AI system. The labs stay where they are. So does the model.

Agentic pipelines

An orchestrator that calls SMRFORGE leaves a trail, not just an answer.

smrforge serve is live today. One local process, pure Python standard library, no web framework, nothing fetched at runtime, so it runs air-gapped. It fronts a REST API and an MCP endpoint. An agent can run a SMRFORGE capability as one step in its workflow and get back a signed evidence bundle.

One step, two doors · 127.0.0.1:8765

# MCP, for agents (JSON-RPC 2.0)
POST /mcp
{ "jsonrpc": "2.0", "id": 7,
  "method": "tools/call",
  "params": { "name": "smrf_run_<capability>",
              "arguments": { ...declared inputs... } } }

-> result content: the signed evidence bundle
# REST, for everything else
POST /v1/run/<capability>
Content-Type: application/json
{ ...declared inputs... }

-> 200, body: the signed evidence bundle
GET  /v1/tools       the open capabilities
GET  /openapi.json   the generated spec

Same bundle through either door. The MCP tool list and the OpenAPI spec are generated from the capability cards, so an agent discovers what it can run with tools/list and the spec cannot drift from the code.

The trail · each step binds to the one before it

step 1 · screening solve
bundle_sha256 sha256:…a1
derived_from none, this is the root
step 2 · reference solve
bundle_sha256 sha256:…b2
derived_from sha256:…a1 · consumed input, pointer, digest
step 3 · shutdown-margin gate
bundle_sha256 sha256:…c3
derived_from sha256:…b2 · consumed input, pointer, digest
reviewer · human or agent
$ smrforge verify step-3.json --chain --from ./chain/
walks every link backwards, offline, nothing fetched

The link lives inside the seal, so the signature covers it. A reviewer walks the chain and re-checks it offline, re-running only the cheap deterministic steps. The orchestrator did not just produce an answer. It produced a trail someone else can audit. Hashes above are illustrative.

Live today

  • smrforge serve, REST and MCP on localhost, standard library only
  • A signed evidence bundle returned per call
  • Sealed derived_from links between steps, binding by content hash
  • smrforge verify --chain walks the links offline

Check it yourself

The three moves a reviewer makes.

No trust in us required. Verify, reproduce, redact. None needs a network.

$ smrforge verify <bundle>

Confirm the seal offline

A standalone checker that imports nothing from our engine. A pass is a real second opinion, not us grading our own homework. Run it on a real bundle in your browser.

$ smrforge reproduce <bundle>

Re-run the open engine

Re-derive the number from the sealed inputs, with the open engine installed. This is what a signed PDF cannot do. It proves the number is real, not just unaltered.

redact

Seal without exposing

Strip a customer’s inputs from a public copy while the seal still verifies. Provably sealed and untampered, inputs never shown.

What the seal proves, and what it does not. Custody, not correctness. A sealed number from a badly specified model is a faithfully preserved wrong answer. Verification against the bundle is not validation against a measurement. SMRFORGE results are screening-to-reference grade, labeled for fidelity, benchmarked against public references on open ENDF/B-VIII data, and advisory. It is not a licensing code.
